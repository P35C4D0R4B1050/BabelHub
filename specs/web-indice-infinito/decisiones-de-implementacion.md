# Decisiones de implementación — web-indice-infinito

Decisiones menores tomadas al implementar que el plan no fija. No cambian el comportamiento de la spec ni de las decisiones D01 a D10 de `decisions.md`.

| Tarea | Decisión | Motivo |
| :--- | :--- | :--- |
| T01 | Las correcciones documentales son: `docs/02/03` (fila «Interfaz web»), `docs/03/04` (fila de módulos y §1.1), `docs/06/03` §3 (ruta con la dirección, validación, sin indexar, enlace desde el inicio), `docs/06/08` §4 (dos filas del catálogo de mensajes: el aviso de texto generado y la dirección no válida) y una sección «Índice infinito» en `docs/glossary.md` («dirección del índice» y «página generada»). | D01 y el plan (T01). |
| T02 | `DireccionDelIndice.Evaluar` devuelve un `ResultadoDeDireccion` (`Estado`, `Direccion` solo si es válida); su `ToString` nunca incluye un texto no válido. `EsValida` queda público para la Aplicación. | IND-07 y CTL-35: el texto recibido no se guarda ni se repite. |
| T03 | `Fnv1a64` y `SplitMix64` son `internal` en el Dominio (visibles a las pruebas); el patrón de oro de `s1-p1-e1-v1-pg1` (primeras y última líneas y SHA-256 de la página) se **calculó con otra implementación (BigInt de Node.js)** a partir de las constantes publicadas, no con el propio generador. | R01: un cambio del algoritmo cambia todas las páginas compartidas; el oro independiente lo hace falsable. |
| T04 | `DireccionAlAzar` suma `TieneLaForma` y `AvanzarPagina` (de 410 vuelve a 1): es la «salida determinista» de D05 y solo acepta una dirección de la forma, porque una dirección que no la tiene nunca coincide con una al azar. Una función de enteros fuera de rango lanza `InvalidOperationException`. | D05 (sin bucle infinito). |
| T05 | El contrato devuelve `ResultadoDelIndice` (`Mostrar`, `Redirigir` o `DireccionNoValida` con la página al azar ya generada), un único tipo para `Abrir` y `Entrar`; `ElegirAlAzar(desde?)` devuelve la dirección. El muestreo por rechazo usa **4 bytes** por sorteo (probabilidad de rechazo menor que 410 / 2^32) con un tope de 8 sorteos fallidos que lanza (equivale a un generador roto) en lugar de girar sin fin. | Plan §1 y §2 (D05); «sin bucle» incluye el rechazo. |
| T06 | `IIndiceInfinito` se registra como **Singleton** (sin estado) y `IAleatoriosSeguros` con `TryAddSingleton`; la prueba de composición vive en `tests/integration/` (como `VersionesDeTextosDeIdentidadTests`) y resuelve el contenedor con dobles de `IUnidadDeTrabajo` e `IConexionDeLaUnidadDeTrabajo` que fallan ante cualquier llamada (cien páginas). | AC-IND-05 «por construcción». |
| T07 | El enlace «El índice infinito» del inicio es un botón fantasma junto a «Sorpréndeme», con `rel="nofollow"`. El mensaje amable lleva `data-bh-foco-inicial` (como las alertas de error del Libro de Reclamaciones). El aviso («Texto generado. Puede carecer de sentido y no son libros reales ni están a la venta.») va en toda página, antes del mensaje amable. «Copiar enlace» lleva el atributo `hidden` hasta que el script lo muestra: sin JavaScript no se ofrece. | D08 y WEB-12. |
| T08 | Una sola acción `Abrir` atiende `GET /indice-infinito`, `GET /indice-infinito/` y `GET /indice-infinito/{**direccion}`; un `direccion` del formulario repetido se trata como no válido pasando al contrato el valor fijo `!` (que nunca es una dirección), de modo que la respuesta amable es la misma y no se repite nada. `Location` se arma solo con una dirección ya validada y se comprueba contra `^/indice-infinito/[a-z0-9-]{1,64}$` (si no coincidiera, lanza). | Plan §1 y T08. |
| T09 | El middleware `CabecerasDelIndiceInfinitoMiddleware` va justo después de `UsarCabecerasDeSeguridad` en `UsarEcommerce`; `robots.txt` es un archivo estático de `wwwroot` (`User-agent: *` y `Disallow: /indice-infinito`). | D06. |
| T07 a T09 | Las tres tareas se commitearon juntas (Api y vista, un solo commit) porque la vista, el controlador y el middleware no compilan ni se prueban por separado; sus pruebas son las de T10 a T13. | Un commit por tarea no es práctico para una pantalla que solo se verifica de punta a punta. |
| T10 a T14 | Las pruebas funcionales, de entrada no válida, de cabeceras, de límite y de arquitectura corren **en memoria y sin Docker**: el MVC real de la Api con sus vistas compiladas (`AnfitrionDelIndice`), la política real de textos pendientes (`AnfitrionConPolitica`, con la ruta no guardada como retorno) y la política real de límites (`EvaluarLimite` con el motor local) sobre las rutas reales. Las pruebas de mutación manuales (quitar `[SinRetorno]`, añadir una dependencia prohibida al caso de uso) hacen fallar la prueba correspondiente. | Docker lo usaba otra corrida; el plan pide el pipeline real, no la base. |
| T11 | `%00`, UTF-8 inválido y una URL mayor que el límite del servidor los rechaza Kestrel antes del pipeline: no se ejercen en memoria (anotado en la clase de pruebas). `%2e%2e` lo normaliza ASP.NET como segmento de punto y queda fuera de la ruta del índice (404 sin eco), así que no se prueba como dirección. | Plan T11. |
| T13 | La prueba de «cero conexiones» registra un doble que cuenta cualquier uso de la unidad de trabajo o de la conexión y Data Protection en memoria; en el host en memoria no hay otra fuente de conexiones, así que **repetirla sobre el host compuesto real (Redis y PostgreSQL) queda para el turno de Docker**, junto con el rechazo 61 con el evento publicado en la base. | Plan §1 (AC-IND-05) y condición de inicio de T13. |
| T15 | El E2E (`tests/e2e/indice/indice-infinito.spec.ts`, 17 pruebas por proyecto) está escrito y **sin correr**: necesita el host de la tienda con datos sembrados (Docker). | Docker ocupado por la corrida de carga. |
