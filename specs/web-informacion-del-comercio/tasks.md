# Tareas — Información del comercio, contacto y política de cambios y devoluciones

> Tareas atómicas ordenadas **de adentro hacia afuera**: Dominio → Aplicación → Infraestructura → Api → Web → pruebas de integración y E2E. Cada tarea cabe en un commit, empieza con una prueba que falla y deja el proyecto compilando. Cada criterio de aceptación de la spec aparece en al menos una tarea. **Nivel de rigor** tras la capa: `C` crítico (arranque con configuración, política de acceso, redirección, versión de los textos), `E` estándar, `B` bajo. **Bloques propuestos:** `COM-1` = T01 a T05 (C: contenido legal y configuración), `COM-2` = T06 a T10 (C y E: redirección, pie, contacto y despliegue), `COM-3` = T11 a T15 (C y E: pruebas y cierre). Las pruebas de cada tarea se escriben primero junto a ella; T11 a T13 las consolidan y completan.

Formato de cada línea: `- [ ] T01 [Capa · Nivel] Descripción (cubre: AC-XXX-01, XXX-01)`.
