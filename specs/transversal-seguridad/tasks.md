# Tareas — Seguridad transversal

> Tareas atómicas ordenadas **de adentro hacia afuera**: Dominio → Aplicación → Infraestructura → Api → Web → pruebas de integración y E2E. Cada tarea cabe en un commit, empieza con una prueba que falla y deja el proyecto compilando. Cada criterio de aceptación de la spec debe aparecer en al menos una tarea. El motor de límites (atómico y concurrente) se prueba temprano con una prueba de humo (T13). Todo vive en el módulo `Plataforma`; **cada tarea se aplica a los dos servicios salvo el motor de Redis (solo E-commerce) y el motor de PostgreSQL (solo Inventario); las pruebas con `Auditoria` real (T27 y T29) exigen `transversal-auditoria` T10, T18 y T25, que se construye después de este plan** (el E-commerce con Redis y el Inventario con PostgreSQL y memoria local) y una prueba de contrato compara las dos copias. Este plan se construye primero: los demás planes dependen de `IReloj`, `IActorActual`, `IUnidadDeTrabajo` e `IControlDeLimites`.
